# Aviation

Two samples, built very differently on purpose.

## `cascade_regional_terminal.mass`

A two-level regional passenger terminal — long-span steel concourse over a ground-level arrivals and
baggage hall, generated by `tools/build_library.py` like the other seven sector samples. Large,
structurally complete, fully reinforced and detailed, with the full LOD 500 record layer on every
element.

Open this one to see what the generator produces at scale.

## `cedar_reach_north_vertiport.mass`

A hybrid heliport / vertiport at a 30% schematic level. **This one was not generated by the tools in
this repository** — it was authored separately and contributed to the library, and it is here
because it does several things the generated samples do not:

- **TLOF, FATO, safety areas and downwash zones modelled as `IfcSpace`**, with the design-basis
  parameters carried in `Pset_Vertiport*` property sets — so the geometry that matters in aviation
  is queryable rather than drawn
- **Five issued aviation sheets** covering geometry and marking, approach/departure and obstacles,
  operational safety, and lighting and controls
- **An approvals register keyed to real regulatory instruments** — airspace notice, layout plan
  amendment, security design approval
- **A design basis that names its own biggest gap first**: no design aircraft has been selected, and
  the report states plainly that TLOF/FATO geometry, deck loads, charger power, downwash and half
  the budget all derive from that choice

It is a smaller model (54 elements) carrying much denser delivery data. That is the right shape for
a 30% package, and it is a useful counterweight to the generated samples, which are geometrically
heavy and deliberately uniform.

### Provenance and what was changed

The package arrived named for a real airport, in a real city, in an archive named for a real eVTOL
manufacturer. Everything in this repository is dedicated to the public domain and carries a hard
rule that no sample names a real place or party — a concept study that reads as a named operator's
project at a named airport is exactly what that rule exists to prevent.

So the identity was replaced, by `tools/rebrand_vertiport.py`:

| Was | Is |
|---|---|
| A real airport name | Cedar Reach North Vertiport |
| A real city and state | Cedar Reach, State |
| A real aircraft manufacturer | Sample Aircraft |
| A real state plane coordinate zone | NAD83 Sample Grid |

**Nothing else changed.** The regulatory references, the preliminary geometry formulas, the design
basis, the registers, the budget, the schedule and the sheets are exactly as contributed — those are
the reason the package is worth including. The rebrand is recorded inside the container itself,
under `manifest.rebranded`, so anyone who unzips it can see what was done and why.

Two things were *added*, because the container was missing them:

- **`geometry/model.frag`**, converted from the source IFC it already contained. Without it the
  sample opens to an empty canvas.
- **A rebuilt manifest inventory.** Substituting text changed byte lengths, so the entry sizes the
  container shipped no longer described its own contents. An inventory that is wrong is worse than
  none — it reads as a verification and is not one.

### Its CSVs came out of the container

The generated samples get their companion CSVs from the same module that produced the container's
rows. A contributed container has no such generator, so its data existed only inside the ZIP — which
made it the one sample in the library you needed software to read.

`tools/export_container_csv.py` closes that from the other direction: it opens any `.mass`, reads
`data/mod_*.json`, and writes the same companion files. The vertiport's budget, schedule, approvals,
risk register, procurement, sheet register, phase gates, cost codes and pro forma beside it are all
exports of its own tables — not a second set of numbers.

It has no space program, because a vertiport's programme is TLOF/FATO geometry rather than a room
schedule. The CI check derives what each sample must carry from what its container actually holds,
so a package is never failed for lacking a table it never had.

### Read the report before citing anything

`cedar_reach_north_vertiport-executive-report.md` opens by stating what the package is not: it is
not sealed engineering, no number in it has been validated by a licensed professional or any
authority having jurisdiction, and every dimension carries an `UNVERIFIED` flag deliberately. That
framing is the most valuable thing in it. A 30% package that does not say it is 30% is how a
schematic sketch ends up quoted as a clearance.
